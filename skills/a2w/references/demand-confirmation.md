# 需求确认规则

## 建议与确认

1. 当前会话已显式激活 `/a2w`，且用户正在整理或修改俱乐部需求时，才可以用宿主已有的本机私人记忆补充缺失或含糊的条件。以用户本次明确表达为准。把推测的值标成待选择的建议，例如「地点还没定，要选西校区吗？」私人记忆原文和来源留在本机。没有可用记忆时，直接问用户。
2. 用户可以接受、修改或拒绝单条建议。把用户明确选择的值和本次提供的条件放入需求卡。列出实际要提交的字段，包括会随请求发送的偏好和变更说明。接受单条建议只代表选择该字段。拒绝的值从卡片中移除，必要条件缺失时再向用户确认。请用户明确确认整张卡，任何修改都需要重新确认。用户暂缓时等待，取消草稿时结束本次整理。
3. 只有用户确认了最后一版卡片，才调用 `submit-demand` 或 `update-demand` 并传入 `--confirmed`。`--preferences-json` 只写卡片上确认的键和值，`--summary` 和 `--change-note` 同样只包含确认内容。私人记忆、被拒绝的值、推断来源和未确认字段均留在本机。已有需求 ID 与重试用的幂等键按工具协议处理。

## 资料边界

- 本机私人记忆的新增、纠正或删除是宿主操作。整理需求时只把用户最终确认的需求值传给托盘。保存到俱乐部资料需要用户另行明确指定要保存的字段。
- `get-profile` 读取俱乐部记录。返回的资料和后台推断只用于当前俱乐部操作；其中的值要进入需求卡，仍须用户确认。Agent 私人记忆只由宿主按用户明确的记忆操作维护。
